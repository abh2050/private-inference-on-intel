Private LLM inference on Intel Xeon: how hard is it, and what do you get?

I installed Intel AI for Enterprise Inference on one IBM Cloud Xeon server, served open models through its OpenAI-compatible gateway, and measured the effort to deploy it, the users one node serves within a latency target, the cost per token, and what Intel AMX contributes.

The problem

Teams that move LLM inference onto their own infrastructure, for cost, data privacy, or air-gap reasons, have to answer four questions before they commit hardware. Vendor documentation answers none of them with numbers:

  1. Effort: how long from an empty machine to an authenticated, OpenAI-compatible endpoint, and where does it break?
  2. Capacity: how many concurrent users does one node serve before latency becomes unacceptable?
  3. Economics: what does a million output tokens cost at that load?
  4. Hardware value: how much of the CPU result comes from Intel AMX?

The latency target was fixed before the run: p95 time to first token (TTFT) of at most 2 s, at least 10 output tokens/s per user, and no failed requests.

What was deployed

Capacity and latency

Same 8 physical cores (one NUMA node) for every model, a ~600-token prompt, 128 output tokens, all traffic through the authenticated gateway. Every request succeeded at every load level.

Output throughput (tokens/s)

Time to first token, p95

  • AMX on: throughput rises to about 217 tokens/s and levels off near 30 users. The target holds through 24 users and fails at 32, when TTFT p95 passes 2 s.
  • AMX off (same cores, oneDNN capped at AVX-512 BF16): throughput stalls near 59 tokens/s and TTFT reaches 8.4 s at 16 users. The target holds for only 2 users.
  • 3B model: answers correctly but gives one user 5.2 tokens/s, below the 10 required at any load. On 8 cores it needs more cores per replica.

What AMX contributes

With one user, AMX adds 1.2×, because decode is limited by memory bandwidth. Under load it adds up to 3.09×, because prompt processing (prefill) is compute-bound and AMX is a matrix unit. At the target, that is 24 users at $2.50 per million tokens with AMX against 2 users at $18.58 without it, on the same hardware.

oneDNN reports the kernel each pod actually ran:

AMX on → brg_matmul:avx10_1_512_amx
AMX off → brg_matmul:avx512_core_bf16

Deployment effort

The install itself was solid: 468 Ansible tasks, none failed, and 49 pods healthy with 0 restarts. The time went to the steps around it. Gray bars are waiting or manual work; blue bars are automation.

Wall clock 48.8 min; automation 32.9 min; three manual interventions before the first correct answer.

Friction found, and the fix for each

IssueWhat happenedSuggested fix
Three repositories, one entry point unclearThe OPEA repo is archived with a “moved” notice; the new inference repo is not installable alone and is driven by a third repo.Point every README at one quick start in enterprise-ai-solutions.
configure stops at an interactive [y/N] promptOver SSH or CI it waits forever (11.4 min here). --force skips it, but the quick start does not mention it.Document --force in the quick start, or detect a non-terminal and say which flag to pass.
validate fails on a healthy clusterIt aborts at nfd, whose validate.yaml is missing in v1.1.0, so the inference components after it are never checked.Skip components without a validate task, and report pass/fail per component instead of aborting.
Token helper breaks strict-mode scriptsget-keycloak-token.sh leaves a RETURN trap that aborts callers running set -u.Clear the trap, or offer a non-sourced command that prints the token.
undeploy returns before cores are freeA deploy issued straight after an undeploy failed NRI pre-flight (“not enough physical cores”) on an empty node.Add undeploy --wait, or have pre-flight wait for terminating pods.
No built-in SLA benchmarkTTFT, tokens/s per user, and cost per token had to be measured with a separate load generator.Ship a model-manager bench that reports these against a stated target.

The current release automates Xeon serving and NVIDIA GPU nodes. Its docs place Intel GPU support in a later milestone, and Gaudi support exists only in the archived OPEA version. IBM Cloud offers Intel Gaudi 3 but no Intel Arc or Data Center GPU instances. This run covers Xeon only.

Routing: a calculated saving

From the measured peak throughputs, sending 70% of requests to the 0.6B model and 30% to the 3B model would cost $7.03 per million tokens against $17.77 for all-3B, a 60% saving. This is arithmetic, not a measured router. An evaluation set would have to show the small model answers that share of real traffic acceptably first.

Limits

  • One server and one run per configuration, so run-to-run variance is not yet measured.
  • The load generator ran on the same server. The model's cores were pinned; the client's were not.
  • Costs use an estimated hourly rate. Rerun analyze.py with the invoiced rate.

Reproduce

About two hours of server time, roughly $3. Every step, log, and benchmark file from this run is in the repository, along with a per-minute operator log.
